# La web y la API se sirven desde el mismo origen

El navegador pide `/api/*` al origen de la web y Next lo reescribe hacia la API (`rewrites` en `apps/web/next.config.mjs`, con destino `API_INTERNAL_URL` o `localhost:4000` en desarrollo); el cliente oRPC usa `window.location.origin` como base, y en SSR `getServerSideProps` llama directamente a `API_INTERNAL_URL` reenviando la cookie (`integrations/auth/server.ts`). El motivo no quedó registrado. Lo que sostiene la decisión son sus consecuencias: la cookie de sesión es del mismo sitio (`httpOnly`, `sameSite: 'lax'`, `auth.cookies.ts`) y la API no necesita CORS (`main.ts` no llama a `enableCors`). Si la web llamara a la API en otro origen, la sesión dejaría de viajar y haría falta CORS con credenciales.
